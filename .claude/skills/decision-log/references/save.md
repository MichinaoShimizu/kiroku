# 保存と索引（decision-log の `write`）

[writing.md](writing.md) で形を確かめてから書く。

## 保存

ファイルを作るか末尾に追記し、下の「索引」のコマンドで索引を作り直す。`--check` が通るまで直す（形の崩れた Decision log も名前を挙げて知らせる）。ブランチを切ってコミットし、PR（MR）を出す。出せなければコミットまでにして、そう伝える。

書いたら番号・ファイル・PR のリンクを伝え、「マージで保存される」と伝える。書けないときは貼れる形で返し、「まだ保存していません」と書く。

## 索引

書いたあとに必ず次を実行する。手で書かない。リポジトリのルートで、スクリプトは相対パスで呼ぶ（Kiro に入れたなら `.kiro/skills/decision-log/scripts/build_index.py`）。絶対パスにしたり、2 つを `;` でつないだりすると、確認なしで通らない。1 つずつ実行する。

```sh
python3 .claude/skills/decision-log/scripts/build_index.py <置き場所>
python3 .claude/skills/decision-log/scripts/build_index.py <置き場所> --check   # 索引が最新で、形の崩れがなければ終了コード 0
```

スクリプトがすること：分類（`category` に「分類を更新」を重ねたもの）ごとに見出しを分け、見出しの直下に分類の中身（[categories.md](categories.md) の表）を書き、「起きたこと」のいちばん古い日付の古い順に並べる。「理由」の 1 行目が「不明」で「分かった」の追記がないものに `・理由不明` を付け、「終了」の追記があるものは最後の「取り下げ」に移す。

```markdown
## 性能・信頼性（reliability）

負荷や障害のときの振る舞い。タイムアウト、リトライ、上限、キャッシュ、縮退

- 2024-11-20 [DL-4](0004.md) 外部 API のタイムアウトが 10 秒から 5 秒になった・理由不明
- 2025-03-04 [DL-1](0001.md) リトライの上限が 3 から 5 になった
```

ほかのブランチと `README.md` が衝突したら、手で直さない。既定のブランチを取り込み、番号が重なっていれば自分の側のファイルの番号を振り直してから、スクリプトで作り直す。
