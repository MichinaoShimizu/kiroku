- Pull requests created by Codex, Kiro IDE / CLI (V3) and Kiro CLI (SQLite) are counted and linked, as they already were for Claude Code: a `gh pr create` run through the agent's shell tool, or a GitHub tool whose name ends in `create_pull_request`, counts when its recorded result is not a failure. They appear on the calendar, in the prompt flow, in session details, in the Output panel and in "Per pull request". Pull requests created by a Codex subagent count in its parent session. kiroku still never asks GitHub. Kiro CLI (V2) and Kiro Crew are not covered, since the shape of their tool results is not public
- Pull requests merged and reviews submitted by AI (`gh pr merge`, `gh pr review`, or GitHub tools that merge or submit a review), with how many reviews were approvals, in the same agents: in the prompt flow ("Merged a pull request", "Approved a pull request", "Reviewed a pull request", with the pull request such as `#12` when the command or tool names it), in session details, and as their own "Merges", "Reviews" and "Approvals" tabs on the Output panel, each with its trend, usual range and change from the previous period. `gh pr merge --auto` only schedules a merge and is not counted; merges and reviews done in a browser, by hand or by other people are not counted
- "What each agent records" in the guide has a "Pull requests created, merged or reviewed by AI" row
- Unit cost per output can divide by merges and by reviews ("Per merge", "Per review"); like Per pull request, the whole period's total is divided
- From input to output flows from agent through project to Change, Commit and PR, as far as each session's work went, including later sessions (a commit within 7 days that includes a file the session changed, and a PR opened from its branch within those 7 days), so you can see how much of the amount reached a commit or a pull request, in which project, and where the rest stopped. Sessions that changed no files are split into GitHub comments and actions, No file changes (tools only) and Chat only
- Other GitHub writes by AI are recorded with a successful result: `gh pr comment|close|reopen|edit|ready`, `gh issue create|comment|close|reopen|edit` and GitHub tools that comment, create or update issues or update a pull request (in the session data as `ghOps`)
